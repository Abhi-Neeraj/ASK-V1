# ASK handoff and next steps (written 2026-11-16)

Everything below is what exists now, how to run it, what was changed in the last working session, what is **not**
proven, and the exact next steps. Read `CLAUDE.md` and `platform/docs/PLAN.md` first. Nothing in this file contains a
secret; every key, password and token lives in a gitignored `.env` file or in the host's own variables.

## 1. What the product is, in one paragraph

A voice locket (Seeed XIAO ESP32S3 Sense) records a meeting when its button is pressed twice (start, stop), stores it on
a memory card, and sends it over **Bluetooth** to the ASK website or phone app. The app uploads the audio to the ASK
server, a worker turns it into a transcript (Google Speech-to-Text) and a summary (Gemini), and the website shows both.

```text
locket (locket_ble firmware) --Bluetooth--> website/phone app (platform/web) --HTTPS--> API (platform/api)
                                                                                         |-- worker -> Google STT + Gemini
                                                                                         '-- database (SQLite local, Postgres hosted)
```

## 5. Run everything locally (Windows)

Prerequisites: Node 24 (WinGet), Python 3.13 venv already at `platform/api/.venv` (the project asks for 3.11; the
Google libraries were installed into the existing venv directly with `pip install google-cloud-speech==2.41.0 google-genai==3.3.0`).

```powershell
# terminal 1: API
cd platform\api
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --port 8000

# terminal 2: worker (without it recordings stay "queued")
cd platform\api
.\.venv\Scripts\python.exe -m app.worker

# terminal 3: website
cd platform\web
npm run build:web
npm run serve:web          # http://localhost:3000
```

Local `.env` (in `platform/api/`, never committed) must hold: `ASK_AI_PROVIDER=google`, `ASK_GOOGLE_STT_API_KEY=...`,
`ASK_GEMINI_API_KEY=...`. Check without printing values:
`.\.venv\Scripts\python.exe -c "from app.config import get_settings as g; s=g(); print(s.ai_provider, s.google_stt_api_key is not None, s.gemini_api_key is not None)"`.
Provider smoke test (sends a generated tone to Google): `.\.venv\Scripts\python.exe -m app.cli ai-check --load`.
Real-speech test: `.\.venv\Scripts\python.exe -m app.cli process-file <a 16 kHz mono wav>`.

## 6. Deploy

**Railway API** (from `platform/api`, after `railway.cmd login`; the project is linked to service `api`):

```powershell
railway.cmd up --service api --ci
```

Variables on the `api` service (names only): `ASK_ENV`, `ASK_SECRET_KEY`, `ASK_LOCKET_MASTER_KEY`, `ASK_DATABASE_URL`
(built from the Postgres service), `ASK_EMAIL_BACKEND=console`, `ASK_COOKIE_SECURE`, `ASK_WEB_ORIGINS`, `ASK_WEB_BASE_URL`,
`PORT=8000`, `RAILWAY_DOCKERFILE_PATH=Dockerfile.railway`, `RAILWAY_RUN_UID=0` (so the container can write the volume),
`ASK_AI_PROVIDER=google`, `ASK_GOOGLE_STT_API_KEY`, `ASK_GEMINI_API_KEY`. Change keys in the Railway dashboard
(service `api` > Variables > **Deploy**); the service restarts. Do not change `ASK_LOCKET_MASTER_KEY`: it would break the
secret of every locket already provisioned.

**Vercel website** (from `platform/web`):

```powershell
npm run build:web
Copy-Item vercel.json dist\vercel.json
cd dist
vercel deploy --prod --yes --name ask-app
```

On Windows PowerShell use `vercel.cmd` and `railway.cmd` if script execution is blocked.

## 7. The locket

Firmware: `platform/firmware/locket_ble`. Board: **XIAO_ESP32S3**, **PSRAM: OPI PSRAM**, esp32 board package **3.3.10 or 3.3.12**.
Compiled and flashed by the owner; works for advertising, pairing and sending a meeting to the phone. Never run on more than
this one board.

Switches in `config.h`:
- `ASK_TEST_PASSKEY` (1234): a fixed pairing PIN. `-1` = the six-digit emailed code (for a real locket).
- `ASK_TEST_NO_PASSKEY` (1): pair with **no code at all**. Anyone nearby can pair. Set `0` before a locket leaves the desk.

Flash: close the Serial Monitor first (it blocks the port: "Access is denied"), Upload with **Erase All Flash Before Sketch
Upload: Disabled**. Enable erase only to wipe the locket's identity.

New identity (a product ID is permanent by design):
1. In the website, Lockets > Register a new locket. Copy the `provision ASK-XXXXXX <secret>` line (shown once).
2. Upload with erase **Enabled**, then Serial Monitor at 115200, line ending Newline: `status` must say "not provisioned".
3. Paste the `provision` line, then `reboot`. Set erase back to Disabled.
4. Remove any saved `ASK-` device in Windows Bluetooth settings and on the phone, then pair from the website
   (Lockets > Find lockets nearby; Chrome or Edge only).

The ID must exist on the **server you pair with**. The secret is derived from that server's `ASK_LOCKET_MASTER_KEY`, so a locket
provisioned from the local server will not pair with the hosted one, and the reverse.

## 8. What works and what is not proven

Proven on the owner's machine:
- Pairing and sending one meeting from the locket to the phone ("meeting ... delivered to the phone").
- Local: Google Speech-to-Text turned a spoken test sentence into correct text; Gemini wrote a summary.
- Hosted: the API, database, volume, Vercel site and the worker start ("started with provider google").

**Not proven / open:**
1. **The server refused the first uploaded recording** ("1 recording was refused by the server and set aside"). The reason
   is unknown. The app now prints it. Next step is to record again and read the message (section 10, step 1).
2. A recording going all the way locket -> phone -> hosted server -> transcript -> website has **not** been seen yet.
3. The Android phone app has never been built. The website in a phone browser is the only phone path so far.
4. The hosted worker's call to Google has not been exercised with a real recording (only its start-up).
5. The locket's recordings are untimed (it has no clock); the phone must send a time. Whether the time arrives correctly is
   unconfirmed and is one suspect for item 1.

  the Railway variables.
- **Rotate the Railway Postgres password** (it was printed once in a tool log; reachable only inside Railway's private network).

- Do not publish this repository publicly: it holds voice-related code, a test hotspot password and deployment identifiers.

## 10. Next steps, in order

1. **Find out why the upload was refused.** On the phone, open https://ask-app-six.vercel.app (reload so it loads the new version).
   Record a sentence of several seconds near the paired locket. Read the new message: it ends with the server's code, for
   example `validation_error: X-Recorded-At is not a plausible time`. Likely fixes by code:

   - A 404 / `not_found`: the signed-in account is not a member of this locket; pair again.

4. **Set up the Android build** for Bluetooth on a phone: `eas.cmd login`, create `platform/web/.env` with

## 11. Useful facts for the next person

- The Bluetooth library path used by the firmware compiles against NimBLE inside board package 3.3.x. The static passkey is
  returned from `BLESecurity::getPassKey()` during the passkey action.
- Railway CLI in Git Bash rewrites `/data` into a Windows path. Set `MSYS_NO_PATHCONV=1` for commands with a leading slash.
- The Railway CLI `ssh` needs an SSH key; migrations are therefore run by the container's start command.
- Windows blocks `.ps1` shims for `vercel` and `railway`; use `vercel.cmd` / `railway.cmd`.
- The `Dockerfile` in `platform/api` is the original and has never been run end to end; Railway uses `Dockerfile.railway`.
